# Fama 数据脱密模块设计方案

## 目标用户

法律共同体（律师、法官、法务、法学研究者），不懂技术。

## 设计原则

1. **零学习成本** - 打开即用，无需配置
2. **一键操作** - 上传文档 → 自动脱密 → 下载结果
3. **法律场景优先** - 预设法律文书常见敏感信息规则
4. **可视化反馈** - 清晰展示脱密前后对比

## 功能设计

### 核心流程

```
用户上传文档 → 自动检测敏感信息 → 显示预览 → 用户确认 → 生成脱密文档
```

> **实现现状（Phase 1 已落地）**：脱密核心已作为内置工具与 CLI 命令集成进
> `packages/opencode`，与 `case_search` / `contract_extract` / `law_search` 等法律工具同构。
> 一键复制脱密副本的诉求通过 `fama redact` 命令满足；脱密工具（`redact`）已注册进
> Agent 工具表，为后续「案件隐私保护识别（beta）」自动提示奠定基础。
> 纯本地处理，不上传任何内容。

## 已实现：CLI 一键脱密（`fama redact`）

把案件材料生成一套「脱密副本」，可安全上传到 AI 平台协同处理。源文件保持不动。

```bash
# 单个文件：就地生成 起诉状.脱密.txt
fama redact 起诉状.txt

# 目录批量：汇总到 ./脱密副本/
fama redact 案件材料/ -o 脱密副本/

# 只检测、不写文件（预览）
fama redact 起诉状.txt --dryRun

# 仅脱敏指定类别
fama redact 起诉状.txt --only idCard,phone,name

# 多文件 + 自定义输出目录
fama redact 原告材料.txt 被告材料.txt -o 脱密副本/
```

支持别名 `fama mask` / `fama 脱密`。`.txt/.md/.markdown` 原样保留扩展名；`.docx` 等
不可读类型降级为 `.md`。

每个脱密副本会附带一份 `*.对照表.md`（占位符 ↔ 原始值），用于本地溯源——
**属敏感信息，切勿随脱密副本一起上传**。

## 已实现：Agent 工具（`redact`）

注册在内置工具表（见 `src/tool/registry.ts`），可被 Agent 调用，或用户在会话中触发。
入参：`text` / `filePath`（二选一）、`categories`（可选，仅脱敏指定类别）、`outputDir`、
`writeCopy`。核心为纯函数，可单测（见 `test/tool/redact.test.ts`、`test/tool/registry.test.ts`）。

### 预设规则（法律场景）

| 规则名称 | 检测内容 | 替换示例 | 涉敏范围 |
|---------|---------|---------|---------|
| 身份证号 | 18 位身份证号（含校验位 X） | [身份证号1] | 个人隐私 |
| 手机号 | 11 位手机号（1[3-9]…） | [手机号1] | 个人隐私 |
| 固定电话 | 区号-座机号 | [固定电话1] | 个人隐私 |
| 银行卡号 | 16~19 位（含 4 位分组） | [银行卡号1] | 个人隐私 |
| 邮箱 | 电子邮箱 | [邮箱1] | 个人隐私 |
| 车牌号 | 含新能源车牌 | [车牌号1] | 个人隐私 |
| 地址 | 直辖市/XX省 + 区县 + 街道门牌 | [地址1] | 个人隐私 |
| 姓名 | 依赖诉讼/合同角色称谓的姓名 | [姓名1] | 个人隐私 |
| 企业名称 | 公司/事务所/集团等 | [企业名称1] | 商业秘密 |
| 涉密标记 | 绝密/机密/秘密/涉密/国家秘密/商业秘密等 | [涉密标记1] | 国家秘密 |

同一敏感值统一替换为同一占位符，保留文档结构与「同一主体」可识别性，便于 AI 继续推理。
案号属公开信息，默认不脱敏。

### 技术实现

#### 模块结构（已实现）

与 `case_search` / `contract_extract` / `law_search` 等法律工具同构，集中在 opencode 包：

```
packages/opencode/
├── src/tool/
│   ├── redact.ts          # 脱密引擎核心（纯函数 detect/redact/buildMapping）+ Tool.define 包装
│   └── redact.txt          # 工具描述（供 LLM 选择）
├── src/cli/cmd/
│   └── redact.ts          # `fama redact` 一键脱密命令（文件/目录批量）
└── test/tool/
    ├── redact.test.ts      # 引擎纯函数单测
    └── registry.test.ts    # 工具已注册进内置列表
```

核心 `detect` / `redact` / `buildMapping` / `summarize` 均为纯函数，不依赖 IO 与 Effect，
便于单测；IO（读文件、写副本）只出现在 `Tool.define` 与 CLI 的外层包装里（遵循
`contract_extract.ts` 的既有范式）。

#### 与 Fama 集成

1. **CLI 一键命令** - `fama redact` 生成脱密副本（已实现）
2. **工具集成** - 已作为内置工具注册进 `src/tool/registry.ts`，Agent 可调用（已实现）
3. **侧边栏入口 / `/mask`** - 待后续 UI 接入（见下方后续扩展）

## 用户体验流程

### 场景1：律师脱密当事人信息

```bash
fama redact 起诉状.txt -o 脱密副本/
# 生成 脱密副本/起诉状.脱密.txt（可安全上传）与 脱密副本/起诉状.脱密.对照表.md（本地保留）
```

### 场景2：法官批量脱密判决书

```bash
fama redact 判决书/ -o 脱密副本/
# 批量处理整个目录，汇总到 ./脱密副本/
```

## 后续扩展

1. **案件隐私保护识别（beta）** - 打开开关后，Agent 在发现案件涉敏感信息（国家秘密/商业秘密/
   个人隐私）时，依据 `redact` 返回的 `scopeHits` 自动提示用户是否先脱密脱敏再处理
2. **自定义规则** - 用户可添加特定脱密规则
3. **模板保存** - 保存常用脱密配置
4. **审计日志** - 记录脱密操作历史
5. **文档解析** - 接入 .docx / .pdf 结构化文本抽取（当前按纯文本处理）

---

## 技术选型

- **前端**：SolidJS + TailwindCSS（与 Fama 一致）
- **后端**：TypeScript（集成到 Fama 核心）
- **文档解析**：
  - Word: mammoth.js 或 docx
  - PDF: pdf-parse
  - TXT: 原生支持
- **正则引擎**：原生 RegExp + 自定义规则引擎
